## 结构对比

| 维度 | 当前 Pixelle | 参考材料有效结构 | Pixelle 选定方向 |
| --- | --- | --- | --- |
| 业务对象 | 项目下拉和项目基础输入已存在，但项目事实较轻 | 先选商品，再补卖点和营销利益 | 使用 ContentProject/ContextSnapshot v2，覆盖门店、品牌、商品、服务和活动 |

## 当前真实基线

使用本地 FastAPI + Vite 和 Codex 内置浏览器，在只读业务页面下采集四个应用：

- 门店营销文案；
- 爆款标题；
- 抖音图文；
- 数字人口播视频。

请求视口：

- 1440×900；
- 1280×800；
- 900×760。

基线目录：

`docs/reviews/application-publishing-program/qa/APP-WORKBENCH-0-baseline-2026-07-28/`

观察：

1. 四个入口都能显示正确应用身份，未出现后端未连接或应用目录不可用；
2. 1440 和 1280 下仍是单列纵向流程，结果和运行记录位于首屏以下；
3. 900 下一级侧栏收缩为图标，但应用输入仍保持单列，没有输入/结果分区；
4. 项目选择器已经存在，可作为后续共享 `ProjectContextSelector` 的迁移起点；
5. 当前 tokens、页头、卡片、按钮和紧凑侧栏可继续复用，不需要新建第二套主题；
6. 当前页面可以安全作为优化前证据，未执行生成、编辑、Provider、浏览器平台或最终发布动作。

## 选定产品原则

1. “选商品”映射为“选择创作项目”，不把 Pixelle 收缩为电商商品工具；
2. 项目保存事实，应用只保存本次任务和表达方式；
3. 左侧控制输入，右侧审阅和交付结果；
4. 风格影响表达，不引入事实；
5. 编辑产生新的 ArtifactVersion；
6. 跨应用必须固定来源版本；
7. 数字人 UI 不复制媒体状态机；
8. 最终发布继续人工确认。
