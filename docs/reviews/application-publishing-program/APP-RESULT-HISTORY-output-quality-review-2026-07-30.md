# 应用中心生成结果产出质量评审

- 日期：2026-07-30
- 范围：爆款标题、抖音图文、数字人历史结果的真实呈现与内容可用性
- 目的：将“历史记录功能正确”与“生成内容本身好用”分开评审

## 1. 门店营销文案

结论：**可用但偏泛，需要在真实发布前补充门店特有事实。**

实际记录一次生成 3 条文案，两个历史批次均能直接比较。现有文案语句顺畅，分别覆盖下午茶场景、实惠便利和上班族人群，基本没有技术话术。

不足：

- 三条都高度重复“现磨咖啡 + 当日面包 + 到店”，差异主要停留在开头。
- 缺少价格、时间、门店位置、限量或明确优惠，转化理由不足。
- “快来试试、约同事打卡”等 CTA 偏通用，没有利用项目里已有的三公里、工作日下午等信息做更具体的行动引导。

建议后续把“候选间差异度、项目事实覆盖率、不可编造事实”作为文案质量规则。

## 2. 爆款标题

结论：**历史呈现通过，标题为可选可改状态，尚未达到无需编辑直接发布。**

- 一次生成的 5 条候选被聚合在同一批次中，便于横向比较。
- 候选可直接复制、编辑、采用，操作位置明确。
- 五条分别覆盖场景痛点、精准人群、解决方案、日常唤起和到店引导，结构差异成立。
- 但“现磨咖啡 + 面包”重复率较高，个别标题如“工作日到店享”表达略生硬；没有价格、时段或具体优惠，也缺少更鲜明的冲突与好奇感。
- 结论是“有可采用候选并适合继续编辑”，不能宣称爆款能力已经由这一个样本证明。

## 3. 抖音图文

结论：**历史呈现通过，当前旧样片的内容质量不通过。**

证据：

- 单成品卡：`evidence/app-result-history-2026-07-30/carousel-history-card.png`
- 全页真实预览：`evidence/app-result-history-2026-07-30/carousel-complete-preview.png`

历史展示符合方案：

- 一次交付只显示一个成品卡。
- 卡片只保留封面、标题、页数和“预览”主操作。
- 点击后直接看到全部实际页面，不再用“第 1 页/第 2 页”Tab 作为主交互。

旧样片质量问题：

- 咖啡/面包营销主题与人物白衣图片关联弱，素材语义不匹配。
- 首屏标题字号过大，信息层级失衡。
- 下半区存在明显空白，画面利用率低。
- 人物边缘与素材构图带来轻微割裂感。

因此该样片不能作为“抖音图文成品质量已通过”的证据。后续应在图文生成链路增加素材语义匹配、版式占用率与标题安全区检查；这属于内容生成质量改进，不阻塞本次只读历史记录与真实预览功能的正确性判断。

## 4. 数字人

结论：**历史呈现与播放通过；样片达到受控可用，视觉质量仍有改进项。**

真实记录：

- Project：`project_54ad306c64814e73b396d9942e8c9fbe`
- AppRun：`run_1135525853084e54a9f6a1936f0f98f1`
- 最终视频：`output/ipb_8d5ca49c_final.mp4`
- 时长：25.76 秒

证据：

- 单视频成品卡：`evidence/app-result-history-2026-07-30/digital-human-history-card.png`
- 真实播放器：`evidence/app-result-history-2026-07-30/digital-human-real-preview.png`
- 播放中帧：`evidence/app-result-history-2026-07-30/digital-human-output-frame-live.png`

通过项：

- 一次交付只显示一个最终视频卡。
- 点击后进入真实 `<video>` 播放器，不展示技术版本清单。
- 视频可实际播放，字幕可见，人物口部与姿态有连续变化。
- 播放器、封面与发布文案均由同一固定 ArtifactVersion 集合投影。

改进项：

- 字幕相对画面偏小，桌面预览可读但移动端传播效果仍需实机抽检。
- 人物动作幅度较克制，长口播的节奏变化有限。
- 仅凭抽帧不能严谨证明逐音节口型同步，口型质量仍应在后续音画专项中测量。

## 5. 总结

本次结果历史功能解决的是“每次生成留下一个可找回、可比较、可直接预览的完整记录”。UI 与真实媒体读取可分别通过；旧图文样片内容质量不通过，数字人样片为受控可用。两者不得混为同一验收结论。
